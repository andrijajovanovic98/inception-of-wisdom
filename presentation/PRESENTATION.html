Inception of Wisdom (IoW)

An autonomous, 100% local self-healing agent loop that continuously observes a containerized service, detects crashes, retrieves context via RAG, synthesizes full-file JSON patches, verifies fixes, and rewinds through Git upon failure.

Subject Cardinal Rule: Everything runs locally. Any call to a remote LLM service (OpenAI, Anthropic, Gemini) is forbidden and results in a grade of zero.

The 4 Beats: Autonomous Self-Healing Loop

The system operates in a perpetual 4-beat cycle governed by state feedback:

 ┌──────────────┐         Error Detected           ┌──────────────┐
 │ 1. OBSERVE   ├─────────────────────────────────►│ 2. THINK     │
 │  (Observer)  │    (Regex logs, 5xx Probes)      │  (Analyst)   │
 └──────▲───────┘                                  └──────┬───────┘
        │                                                 │ Top-k AST Chunks
        │ Verification                                    │ & LLM Diagnosis
        │ (20s Grace Period)                              ▼
 ┌──────┴───────┐        Atomic File Patch         ┌──────────────┐
 │ 4. VERIFY    │◄─────────────────────────────────┤ 3. ACT       │
 │  (Verifier)  │      Commit on iow/auto-heal     │ (Wisdom Loop)│
 └──────────────┘                                  └──────────────┘
  (Failure after 3 attempts restores only heal-scoped demo_app/ paths)

Deterministic Decision Tree

The agent does not blindly patch. Hard signals (crashes, 5xx, exit != 0) trigger the loop. Soft signals (4xx functional suggestions) are surfaced for humans only.

Self-Bounded Safety

Strict guardrails: max 3 attempts per cycle, pre-disk sanity checks, single-flight locking, per-signature cooldown, and a dynamic kill switch.

Containerized Deployment & Local LLM

One docker compose up

  • make up = docker compose up --build -d: the agent, the LLM runtime, the target and the Gitea forge.
  • demo_app: Flask target (port 5001:5000), bind-mount ./demo_app:/app, STOPSIGNAL SIGINT so a restart takes well under a second.
  • agent: dashboard on :8000, with the Docker socket ($DOCKER_SOCK, the rootless socket on campus), the checkout at /workspace and /tmp/iow mounted.
  • File ownership: scripts/agent_entrypoint.sh runs the agent as the owner of the checkout — on rootful Docker it drops to that uid, on rootless Docker the host user already is uid 0 inside.

Local Model Runtime

  • ollama service: ollama/ollama pulls the model into a volume on first start and reports healthy once it is there; the agent reaches it as http://ollama:11434 (no host port).
  • Host runs (make p1 ... make bonus) use the Ollama make setup starts on :11436.
  • Model: qwen2.5-coder:1.5b (1.54 B parameters, under the 3 B limit).
  • Embedding: all-MiniLM-L6-v2, cached in /tmp/iow/hf-cache and loaded offline.
Defense Tip: Evaluators check that no cloud API is called. Every endpoint the agent talks to is local: Ollama, the target and Gitea — see OLLAMA_HOST in docker-compose.yml.

Part 1: Observer (The Nervous System)

Docker Monitor

State and events of the target, from the Docker daemon:

  • Non-zero exit, from the event stream (the restart policy hides it from polling)
  • Restart loop (counter climbing, or stuck restarting)
  • Dead / OOM-killed state
  • Survives a daemon outage and reconnects

Real-Time Log Streamer

Streams stdout / stderr in near real time:

  • 500-line thread-safe ring buffer
  • Configurable regex error patterns (target.error_patterns)
  • One traceback = one incident; replayed history never re-fires
  • Live SSE stream to the dashboard

HTTP Probing & Signal Separation

Probes target.probe_urls every 3 s (/, /healthz, /api/missing-route):

  • 2xx: Healthy baseline
  • 4xx: Soft functional suggestion (NOT patched automatically)
  • 5xx / refused / timeout: Hard crash signal
Sliding-Window Deduplication: one incident = one event with a counter (90 s window, longer than Docker's 60 s maximum restart backoff; 300 s for suggestions). The incident ends once the target serves again or a heal is verified.

Part 2: Analyst (Semantic Retrieval & Diagnosis)

AST Logical Chunking (chunker.py)

  • Subject forbids fixed-size chunking (e.g. 500 characters).
  • Uses Python ast: one chunk per function, class and method, plus module blocks and the __main__ block — every line is in a chunk.
  • SHA-256 per chunk: unchanged chunks are never re-embedded.
  • ChromaDB PersistentClient in /tmp/iow/chroma_db; watch mode re-indexes changed files every 3 s and prunes what disappeared.

Traceback Guided Top-k Retrieval

  • Looks the traceback's functions and file:line frames up in the index itself.
  • Merges them with a cosine top-k search over local all-MiniLM-L6-v2 embeddings.
  • Only those chunks go into the prompt — the model chooses, it does not invent.

Structured Diagnosis JSON & Anti-Hallucination

Enforces strict JSON schema: {"summary": "...", "files": ["relative/file/path"]}. Cross-validates cited files against real indexed files — the pipeline refuses to guess or touch imaginary paths.

Part 3: Wisdom Loop (Action & Rollback)

Diff-Free JSON Patcher

The patch is {summary, files: [{path, op, content}]} with the complete post-change file, op one of create / modify / delete; diffs are refused. In a larger file the model rewrites only the chunk the crash points at and the patcher builds the full-file patch (analyst.patch_strategy: full_file has the model write it whole).

Sanity Bounds (Pre-Disk)

  • Touches at most 3 files
  • No trivial placeholder
  • Max 60% file shrinkage
  • No leaked retrieval markers
  • Only demo_app/, never iow.config.yml
  • Must parse, must change something, may not drop a definition

GitManager & Branching

Records the exact state demo_app/ runs as the pre-loop revision (a snapshot commit when it differs from HEAD), writes atomically (*.iow.tmp + fsync + os.replace) and commits on iow/auto-heal with git plumbing — HEAD, the index and the checked-out branch never move.

The 3-Attempt Guarantee: after 3 failed attempts iow/auto-heal is rewound to the pre-loop revision, demo_app/ is restored from it through a throwaway index, re-hashed and shown as identical, and the target restarts on it. A cycle cut short by an agent stop is rolled back on the next start.

Dynamic Safety Guardrails (iow.config.yml)

Hard-coded timings are strictly forbidden by subject. All parameters are dynamically read from disk:

The 5 Non-Negotiable Bounds

  • Single-Flight: Exactly 1 heal cycle at a time. Locks out race conditions.
  • Cooldown per Signature: Wait 300s before retrying the same crash signature.
  • Rate Limit: Max 5 heals started per rolling hour.
  • Hard Cap: Max 20 lifetime heals per process.
  • Global Kill-Switch: Flip kill_switch: true to instantly freeze healing.

Dynamic mtime Reloader

The SafetyManager monitors the modification time (mtime) of iow.config.yml. Changing a parameter takes effect immediately without restarting the agent or container!

# demo_app/iow.config.yml
grace_period: 20
cooldown: 300
rate_limit_per_hour: 5
hard_cap: 20
boot_timeout: 45
kill_switch: false

Chapter VI: Bonus Part Enhancements

Tiny Symptom Classifier

Learns every verified heal together with the code it was applied to. The same crash on the same code is healed from the cached patch without calling the LLM: the restart plus the grace period (24 s with the default 20 s) instead of 45-80 s. A cached patch that fails loses trust.

Second Opinion Consensus

Two prompts (conservative stack frame vs caller contract) must agree on the suspect file — on every attempt, retries included. A divergence is never patched autonomously. Off by default, toggled in the Bonus tab.

Human-in-the-Loop PRs

With HITL on nothing lands before a human approves: a review PR (iow/review/<cycle>) on the local Gitea with its diff. Approving deploys it under the heal bounds and keeps it only if the target stays up.

Gitea runs with make up (or the host run make pr-bonus) on :3000. GitOps: make argocd-bonus (campus-safe iow-k3s, Argo UI :8080 or IOW_ARGOCD_PORT, demo NodePort :30051); plant a bug in the cluster with make break-import gitops-publish. There the heal commit alone redeploys: it stamps its code's hash into the pod template, and Argo CD syncs it and rolls the pod.
