Inception of Wisdom (IoW)

An autonomous, 100% local self-healing agent loop that continuously observes a containerized service, detects crashes, retrieves context via RAG, synthesizes full-file JSON patches, verifies fixes, and rewinds through Git upon failure.

Subject Cardinal Rule: Everything runs locally. Remote LLM API calls (OpenAI, Anthropic, Gemini) are strictly forbidden (instant 0 XP).

The 4 Beats: Autonomous Self-Healing Loop

The system operates in a perpetual 4-beat cycle governed by state feedback:

 ┌──────────────┐         Error Detected           ┌──────────────┐
 │ 1. OBSERVE   ├─────────────────────────────────►│ 2. THINK     │
 │  (Observer)  │    (Regex logs, 5xx Probes)      │  (Analyst)   │
 └──────▲───────┘                                  └──────┬───────┘
        │                                                 │ Top-k AST Chunks
        │ Verification                                    │ & LLM Diagnosis
        │ (20s Grace Period)                              ▼
 ┌──────┴───────┐        Atomic File Patch         ┌──────────────┐
 │ 4. VERIFY    │◄─────────────────────────────────┤ 3. ACT       │
 │  (Verifier)  │      Commit on iow/auto-heal     │ (Wisdom Loop)│
 └──────────────┘                                  └──────────────┘
  (Failure after 3 attempts rewinds auto-heal branch byte-for-byte)

Deterministic Decision Tree

The agent does not blindly patch. Hard signals (crashes, 5xx, exit != 0) trigger the loop. Soft signals (4xx functional suggestions) are surfaced for humans only.

Self-Bounded Safety

Strict guardrails: max 3 attempts per cycle, pre-disk sanity checks, single-flight locking, per-signature cooldown, and a dynamic kill switch.

Containerized Deployment & Host LLM Bridge

Multi-Service Docker Stack

  • demo_app: Containerized target Flask service (port 5001:5000) with bind-mount ./demo_app:/app.
  • agent: IoW orchestrator and web dashboard (port 8000:8000).
  • /var/run/docker.sock: Bound directly into the agent container for container lifecycle control.
  • UID / GID Matching: Agent runs with host UID 101888 and GID 4224 so disk writes preserve exact repository ownership.

Offline Host LLM Connection

  • Ollama on Host: The model runtime runs locally on the host to avoid nested virtualization.
  • Bridge Mapping: host.docker.internal:host-gateway maps container network to host bridge gateway (172.17.0.1).
  • Model: qwen2.5-coder:1.5b (< 3B parameters).
  • Embedding: all-MiniLM-L6-v2 cached offline in /tmp/iow_cache/.
Defense Tip: Evaluators will check if any cloud APIs are used. Show them docker-compose.yml extra_hosts pointing to host.docker.internal:11434!

Part 1: Observer (The Nervous System)

Docker Socket Monitor

Inspects the target container directly via Docker SDK:

  • Exit code != 0 detection
  • Restart loop detection
  • Dead / OOMKilled state
  • Container restart trigger

Real-Time Log Streamer

Streams stdout / stderr in near real time:

  • 500-line thread-safe ring buffer
  • Regex error matcher (Traceback, CRITICAL, Error, Exception)
  • Emits real-time SSE stream to dashboard

HTTP Probing & Signal Separation

Probes / and /healthz every 3s:

  • 2xx: Healthy baseline
  • 4xx: Soft functional suggestion (NOT patched automatically)
  • 5xx / Timeout: Hard crash signal
Sliding-Window Deduplication: Generates SHA-256 signatures. A single bad restart produces 1 crash event with an incremented counter, not a flood of 100 events per minute.

Part 2: Analyst (Semantic Retrieval & Diagnosis)

AST Logical Chunking (chunker.py)

  • Subject forbids fixed-size chunking (e.g. 500 characters).
  • Uses Python ast module to split along logical function and class boundaries.
  • Calculates SHA-256 hash per chunk for incremental indexing.
  • ChromaDB PersistentClient in .chroma skips unchanged chunks across restarts.

Traceback Guided Top-k Retrieval

  • Extracts exact stack frame symbols, line numbers, and exception names from crash logs.
  • Runs cosine similarity search using local all-MiniLM-L6-v2 embeddings.
  • Passes candidate code slices into local Ollama coder prompt.

Structured Diagnosis JSON & Anti-Hallucination

Enforces strict JSON schema: {"summary": "...", "files": ["relative/file/path"]}. Cross-validates cited files against real indexed files — the pipeline refuses to guess or touch imaginary paths.

Part 3: Wisdom Loop (Action & Rollback)

Diff-Free JSON Patcher

Diffs are strictly forbidden by subject. Emits complete post-change file contents: {summary, files: [{path, op, content}]}.

Sanity Bounds (Pre-Disk)

  • Touches at most 3 files
  • Max 60% file shrinkage
  • No empty or placeholder files
  • No leaked retrieval markers
  • Python syntax compilation check

GitManager & Branching

Snapshots pre-loop revision hash. Applies files atomically via os.replace. Commits to dedicated iow/auto-heal branch.

The 3-Attempt Guarantee: If after 3 repair attempts the target fails grace period verification, GitManager immediately runs git reset --hard <pre_loop_hash>, restarts the container, and leaves the repository in a clean state.

Dynamic Safety Guardrails (iow.config.yml)

Hard-coded timings are strictly forbidden by subject. All parameters are dynamically read from disk:

The 5 Non-Negotiable Bounds

  • Single-Flight: Exactly 1 heal cycle at a time. Locks out race conditions.
  • Cooldown per Signature: Wait 300s before retrying the same crash signature.
  • Rate Limit: Max 5 heals started per rolling hour.
  • Hard Cap: Max 20 lifetime heals per process.
  • Global Kill-Switch: Flip kill_switch: true to instantly freeze healing.

Dynamic mtime Reloader

The SafetyManager monitors the modification time (mtime) of iow.config.yml. Changing a parameter takes effect immediately without restarting the agent or container!

# demo_app/iow.config.yml
grace_period: 20
cooldown: 300
rate_limit_per_hour: 5
hard_cap: 20
kill_switch: false

Chapter VI: Bonus Part Enhancements

Tiny Symptom Classifier

Caches verified fixes for crash symptoms. When a known symptom occurs, it bypasses the LLM entirely (Fast Path), reducing repair time from 20s to 0.01s.

Second Opinion Consensus

Prompts two independent diagnostic angles (Conservative Stack vs Architectural Contracts). A patch is only triggered if both opinions agree on the suspect file.

Human-in-the-Loop PRs

Instead of unattended commit, creates review branch iow/review/*, unified diff preview, and dashboard button for human review and merge.

All bonus components are organized cleanly under the bonus/ directory, keeping the mandatory parts pristine.
