Part 3: Wisdom Loop - Autonomous Remediation

The Wisdom Loop turns diagnostic insights into verified source code repairs. It coordinates diff-free JSON patching, multi-stage sanity checks, atomic Git branch management, Docker container lifecycle restarts, active verification polling, and automatic multi-attempt rollback.

Subject Requirement: "Act on diagnosis: generate patch, apply changes, verify container recovery. Enforce safety bounds, rate limits, cooldown, hard caps, and kill-switch. Roll back automatically if verification fails after up to 3 attempts."

Diff-Free JSON Patching (p3/patcher.py)

Why Unified Diffs Fail with Small LLMs

Standard diffs (@@ -12,4 +12,6 @@) require exact character counts and line offset mathematics. Models under 3B parameters consistently hallucinate diff headers, producing malformed patches that patch(1) rejects.

Structured JSON File Replacement

{
  "summary": "Fix ZeroDivisionError with guard",
  "files": [
    {
      "path": "demo_app/app.py",
      "op": "replace",
      "content": "... entire valid python code ..."
    }
  ]
}
  • Enforces complete file replacement or creation.
  • No ambiguous patch hunk offsets.
  • System prompts strictly mandate syntactically complete code.

Sanity Bounds & Guardrails (p3/sanity.py)

Pre-Disk Safety Screening

Before any generated patch touches the filesystem or Git tree, it must pass 4 strict validation filters:

  • File Count Bound: Max 3 files modified in a single remediation flight (prevents wholesale repo disruption).
  • Shrinkage Guard: Max 60% byte size reduction compared to the original file (protects against accidental code deletion).
  • Anti-Placeholder Heuristic: Blocks patches containing lazy AI tokens like # TODO, # rest of code here, or # implement here.
  • Syntax Validation: For Python targets, runs ast.parse(content) to reject syntax errors before disk write.

Git Isolation & Atomic Commits (p3/git_manager.py)

Dedicated Healing Branch

  • All self-healing work occurs on isolated branch: iow/auto-heal.
  • Captures pre-loop revision (base commit SHA) before any modification.
  • Atomic file writing: writes to temp files before renaming to avoid partial writes.
  • Creates explicit Git commit with diagnostic summary and attempt counter.

Automatic Hard Rollback

Guaranteed Zero-Corruption: If verification fails after maximum attempts (3), the loop triggers: git reset --hard <pre_loop_sha> The original codebase state is completely restored without developer intervention.

Container Restart & Verification (p3/verifier.py)

Docker Engine Restart

  • Interacts with host Docker daemon via /var/run/docker.sock.
  • Restarts target container via Docker Engine API: POST /containers/{id}/restart.
  • Captures new container state and exit status.

Active Grace Period (20s)

  • Does not immediately assume success upon container up.
  • Polls HTTP health endpoints (/health, /crash) across the grace window.
  • Continuously monitors container logs for immediate re-crash loops or unhandled exceptions.

Feedback Loop & Retry Orchestration (p3/loop.py)

Adaptive Multi-Turn Healing

A single attempt may not fully resolve deep architectural bugs. The Wisdom Loop adapts across 3 turns:

Attempt 1: Initial Diagnosis -> Patch -> Restart -> Verification Fails!
                 │
                 ▼ (Feedback: Container exited with status 1, Traceback included)
Attempt 2: Augmented Prompt with Failure Context -> Refined Patch -> Pass!
                 │
                 └─ If Attempt 3 fails: Automatic Git Reset --hard
  • Error output from Attempt 1 is injected into the Attempt 2 prompt as explicit feedback.
  • Enables the 1.5B LLM to correct its own previous mistakes iteratively.

Safety Controls & Dynamic Limits (p3/safety.py)

iow.config.yml Constraints

  • Single-Flight Lock: Only one healing loop can run concurrently.
  • Cooldown: Enforces quiet time between loop runs (e.g. 60s).
  • Rate Limit Per Hour: Caps maximum repairs per rolling 60-minute window (e.g. 10/hr).
  • Hard Cap: Absolute maximum allowable repairs before requiring human intervention.

Emergency Kill-Switch

Subject Requirement: Setting kill_switch: true in iow.config.yml immediately disables the loop without restarting the agent!

Part 3 Peer-Evaluation Checklist

Key Questions Evaluators Will Ask:

  • Q: Why did you not use git apply with unified diff?
    A: LLMs < 3B hallucinate line offsets in diff headers. Full-file replacement eliminates syntax patch corruption while staying within sanity limits.
  • Q: What prevents the AI from deleting the whole codebase to 'fix' a bug?
    A: Sanity checks enforce a max 3 file limit, 60% shrinkage guard, and AST syntax validation before any disk write.
  • Q: How do you prove rollback works during the defense?
    A: Trigger an unfixable syntax or configuration error; observe the agent exhaust 3 attempts, execute git reset --hard, and return the working directory to the pre-loop revision.
