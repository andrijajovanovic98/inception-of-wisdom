CHAPTER VI BONUS

Bonus Suite: Beyond Autonomous Healing

Chapter VI extends the self-healing loop: a symptom classifier that heals a known crash from its verified patch without the LLM, a dual-prompt "Second Opinion" that only patches on agreement, Human-in-the-Loop pull requests on a local Gitea, and a GitOps redeploy through Argo CD.

Subject (VI): "Train a tiny classifier on past events to skip the LLM entirely on known-symptom crashes." — "Add a "second opinion" mode where two prompts vote on the same diagnosis and only an agreement triggers the patch."

Tiny Symptom Classifier (bonus/classifier.py)

The Problem with LLM Latency

On CPU, qwen2.5-coder:1.5b takes 13-16 s for a diagnosis and another 10-20 s for a patch: a heal through the model takes 45-80 s end to end. A crash the agent has already healed does not need the model again.

Fast Path (no model call)

  • A symptom key from the traceback: exception type, the deepest frame in the app's own code (not the stdlib's <frozen os>), function and normalised message.
  • Exact or nearest-neighbour match; at confidence ≥ 0.85 attempt 1 replays the cached verified patch — no retrieval, no LLM. What is left is the restart and the grace period: 24 s end to end with the default 20 s grace period (about 13 s with grace_period: 8).
  • Only onto exactly the code it was learned on (the pre-heal hash of every file it replaces); on changed code the model is asked instead of reverting unrelated edits.
  • Still passes the sanity gate and verification; a cached patch that fails loses trust (−0.25) and is evicted below 0.40.

"Second Opinion" Consensus Engine (bonus/consensus.py)

Eliminating Single-Prompt Hallucination

Small 1.5B LLMs can be sensitive to phrasing. The consensus engine issues two distinct reasoning prompts to the local model:

Perspective A (Root Cause Focus):

Examines raw stack trace and runtime execution flow.

Perspective B (Defensive Architecture):

Examines call-site contracts, edge cases, and input validation.

Only an agreement patches: both opinions must cite the same suspect file — on every attempt (a divergence on a retry is a failed attempt). A divergence before the first attempt goes to a review PR, or is withheld when no forge is reachable; it is never applied autonomously. Off by default (second_opinion_mandatory, Bonus tab).

Human-in-the-Loop PR Manager (bonus/pr_manager.py)

Enterprise Safe Mode

In production environments, fully autonomous code writes to production branches can be prohibited by governance policy.

  • The sanity-checked patch becomes a review branch iow/review/<cycle>, built from the patch files only with git plumbing — the working tree is untouched.
  • Its own base branch iow/base/<cycle> (what the target runs): the PR diff is exactly the patch.
  • Nothing is written or restarted before approval.

Bonus API Endpoints (bonus/bonus_api.py)

FastAPI Bonus Router

  • GET /api/bonus/classifier/stats: Returns learned symptom and verified-heal cache statistics.
  • POST /api/bonus/consensus/evaluate: Runs dual-prompt evaluation and returns the consensus report.
  • GET /api/bonus/prs: Lists pending Human-in-the-Loop pull requests.
  • POST /api/bonus/prs/create: Creates a review branch and local/Gitea pull request.
  • POST /api/bonus/prs/{pr_id}/merge: Operator approves and merges the PR; /approve is an alias.
  • POST /api/bonus/prs/{pr_id}/reject: Operator rejects the PR and discards its review branch.

Gitea HITL & Argo CD GitOps Operations

Auditable Gitea Review

  • make up starts Gitea with the rest of the system (host run: make pr-bonus).
  • Review local pull requests in Gitea at http://127.0.0.1:3000.
  • Merge or reject from the dashboard/API with an auditable operator decision; an approval merges the PR on Gitea too (waiting while Gitea still checks it).

Campus-Safe GitOps Redeploy

  • make argocd-bonus creates privileged iow-k3s, not nested k3d.
  • Argo CD syncs k8s/demo-app from local Gitea; the pod clones the heal branch at start.
  • make break-import gitops-publish plants a bug in the cluster. Every commit stamps its code's git tree hash into the pod template (iow.42/source), so the commit alone redeploys: Argo CD (reconciling every 15 s) syncs it and rolls the pod. The agent pushes and waits — it asks for a sync only if nothing moved in 75 s — and keeps the fix once a pod of that code is Ready and stays up for the grace period.
  • Argo UI: :8080 (IOW_ARGOCD_PORT moves it); demo NodePort: :30051.
Defense Tip: Show the PR in Gitea first, then show Argo CD reporting the desired state synced and healthy.

Chapter VI Peer-Evaluation Checklist

Key Questions Evaluators Will Ask:

  • Q: Does the bonus part violate the local-only constraint?
    A: No. Both prompts of the second opinion use the same local model (qwen2.5-coder:1.5b), the classifier is local code over a local store, and Gitea and Argo CD run on this machine.
  • Q: Why is the Fast-Path Classifier useful if we already have RAG?
    A: A crash it has healed before is healed again from the verified patch in the restart plus the grace period (24 s with the defaults) instead of 45-80 s, without calling the model — even with Ollama stopped. It only replays onto the exact code it was learned on.
  • Q: What happens if an operator rejects a pending PR?
    A: The Gitea PR is closed and the review branch deleted; nothing was ever written to the target, and the PR is recorded as rejected with the reviewer's reason.
