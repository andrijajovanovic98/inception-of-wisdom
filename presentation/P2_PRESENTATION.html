Part 2: Analyst — Semantic Code Intelligence

The Analyst bridges runtime crash symptoms with source code semantics. It decomposes the target codebase into logical AST chunks, indexes them into a local vector database, retrieves relevant code slices, and synthesizes a structured diagnosis using an offline LLM (< 3B).

Subject (V.2): "The diagnosis output is structured (JSON, with at least a summary field and a files list of suspect paths)." — "The diagnosis must cite real files from the index. It must not invent paths."

AST Logical Chunking (p2/chunker.py)

Why Fixed-Size Chunking Fails

Naive chunking (e.g. 500 characters) cuts functions in half, breaks syntax, and destroys variable scope. The subject explicitly forbids arbitrary fixed chunking.

AST-Based Decomposition

  • Parses Python files with the built-in ast module.
  • Identifies ast.FunctionDef, ast.AsyncFunctionDef, and ast.ClassDef.
  • Preserves leading decorators and exact start/end line bounds.
  • Every top-level statement belongs to a chunk: the module preamble (imports, globals), module blocks between definitions, and the if __name__ == "__main__": block — where a bad environment variable crashes.
  • Assigns a deterministic SHA-256 hash to each chunk.

ChromaDB & Offline Embeddings (p2/db.py)

PersistentClient Mode

  • Uses chromadb.PersistentClient(path="/tmp/iow/chroma_db") via CHROMA_CACHE_DIR.
  • Incremental updates: Compares chunk SHA-256 against stored metadata. Only newly modified functions are re-embedded.
  • Subject rule: The index must survive restarts and never rebuild from scratch on boot.
  • Watch mode (p2/watcher.py): every 3 s (analyst.watch_interval_seconds) changed files are re-chunked; moved code gets its new line numbers without re-embedding, removed symbols and files are pruned.

Local all-MiniLM-L6-v2 Embedding

  • Completely offline 384-dimensional dense vectors.
  • Models cached in /tmp/iow/ to protect student 42 disk quota.
  • No network connection needed during runtime.

Traceback-Guided RAG Retrieval (p2/retriever.py)

Identifier & Stack Frame Extraction

Scans the crash log with compiled regular expressions:

# make break-env - file, line, exception type
File "/app/app.py", line 92, in <module>
KeyError: 'IOW_DEMO_PORT'

Looks them up in the index itself (the subject's hint): functions by symbol name, file:line frames by the chunk's line range.

Hybrid Ranking (Symbol + Semantic)

  • Priority 1: the chunk that contains the traceback's line.
  • Priority 2: a function the traceback names, then the file.
  • Cosine similarity breaks ties; top-k is analyst.top_k.
  • Returns chunks with metadata: {file_path, symbol_name, start_line, end_line, score}.

Structured LLM Diagnostician (p2/diagnostician.py)

Ollama Coder Prompt (< 3B)

  • Model: qwen2.5-coder:1.5b, run locally (the compose ollama service, or the host Ollama for host runs).
  • Enforces JSON schema: {"files": ["demo_app/app.py"], "summary": "..."}.
  • Feeds only the retrieved chunks into the prompt, with the allowed files: the model chooses, it does not invent.

Anti-Hallucination Validation

The Pipeline Does Not Guess: Small 1.5B models can hallucinate non-existent files. Every cited file is checked against the indexed files; unknown or ambiguous paths are dropped. No usable file or summary — or no model at all — is reported as an explicit failure, never filled in.

Analyst REST Endpoints (p2/analyst_api.py)

FastAPI Endpoints

  • GET /api/analyst/status: Total chunks indexed, embedding model name, LLM model.
  • POST /api/analyst/sync: Re-scans repository and applies incremental updates.
  • POST /api/analyst/retrieve: Free-text semantic code search with similarity scores.
  • POST /api/analyst/diagnose: Diagnoses an incoming error log and returns structured JSON.
Defense Tip: In the dashboard's 2nd tab, run a free-text search (e.g. "the startup configuration and port") and show the evaluator the top-k chunks with their similarity scores.

Part 2 Peer-Evaluation Checklist

Key Questions Evaluators Will Ask:

  • Q: Why AST chunking instead of LangChain RecursiveCharacterTextSplitter?
    A: Subject requirement. AST guarantees that code chunks respect function and class boundaries, preventing broken syntax from reaching the LLM.
  • Q: Does ChromaDB wipe the database when the container restarts?
    A: No. It runs in PersistentClient mode under /tmp/iow/chroma_db and updates incrementally based on chunk SHA-256 hashes.
  • Q: How do you prevent the 1.5B model from hallucinating?
    A: Traceback symbols anchor the context, and output file paths are cross-checked against actual known indexed files.
