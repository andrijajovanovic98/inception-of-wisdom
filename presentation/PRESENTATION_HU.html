42 BUDAPEST — AUTONÓM ÖNGYÓGYÍTÓ ÁGENS

Inception of Wisdom (IoW)

Egy 100%-ban helyi, autonóm öngyógyító ágens-hurok, amely folyamatosan felügyel egy konténerizált szolgáltatást, észleli a hibákat, szemantikus RAG-kereséssel kontextust gyűjt, diff-mentes JSON javítást szintetizál, és sikertelenség esetén a Git segítségével automatikusan visszaállítja a kódot.

Szigorú Subject Szabály: Minden kizárólag helyben futhat. Külső LLM API-k (OpenAI, Anthropic, Gemini) használata tilos és azonnali bukást (0 XP) von maga után.
Navigáció: Jobbra nyíl vagy Következő gomb.

A 4-Ütem: Autonóm Öngyógyító Hurok

A rendszer egy folyamatos, zárt 4-ütemű ciklust valósít meg állapot-visszacsatolással:

 ┌──────────────┐         Hiba Észlelése           ┌──────────────┐
 │ 1. OBSERVE   ├─────────────────────────────────►│ 2. THINK     │
 │  (Observer)  │    (Regex logok, 5xx szondák)    │  (Analyst)   │
 └──────▲───────┘                                  └──────┬───────┘
        │                                                 │ Releváns AST chunkok
        │ Verifikáció                                     │ & LLM Diagnózis
        │ (20s Grace Period)                              ▼
 ┌──────┴───────┐        Atomi Fájl Patch          ┌──────────────┐
 │ 4. VERIFY    │◄─────────────────────────────────┤ 3. ACT       │
 │  (Verifier)  │      Commit az iow/auto-heal-en  │ (Wisdom Loop)│
 └──────────────┘                                  └──────────────┘
  (3 sikertelen kísérlet után: Git reset --hard visszaállítás az eredetire)

Jelosztályozási Döntési Fa

A rendszer nem végez vaktában javítást. A hard jelek (crashek, 5xx hibák, nem-nulla exit) azonnal indítják a hurkot, míg a soft szuggesztiók (4xx hiányzó végpontok) csak megjelennek a dashboardon az ember számára.

Önkorlátozó Biztonság

Szigorú korlátok: max 3 próbálkozás egy ciklusban, írás előtti sanity ellenőrzések, single-flight zár, cooldown és dinamikus vészleállító (kill switch).

Konténerizáció és Helyi Ollama Hálózat

Több-konténeres Docker Stack

  • demo_app: Konténerizált Flask célalkalmazás (5001:5000 port) ./demo_app:/app kötéssel.
  • agent: IoW ágens és FastAPI dashboard (8000:8000 port).
  • /var/run/docker.sock: Csatolva az ágensbe a konténer újraindításához és vizsgálatához.
  • UID / GID Matching: Az ágens a host felhasználó (101888/4224) jogaival fut, elkerülve a fájljogosultsági hibákat a bind mounton.

Offline Host LLM Kapcsolat

  • Helyi Ollama: A modell a hoston fut az erőforrások kímélése érdekében.
  • Bridge Híd: host.docker.internal:host-gateway biztosítja a kapcsolatot a belső hálózaton (172.17.0.1:11434).
  • Modell: qwen2.5-coder:1.5b (< 3B paraméter, a subject előírása szerint).
  • Embedding: all-MiniLM-L6-v2 offline cache a /tmp/iow_cache/-ben (42 kvótavédelem).
Defense Tipp: Az értékelők ellenőrizni fogják, hogy külső API-t hívsz-e. Mutasd meg nekik a docker-compose.yml-ben az extra_hosts és a host.docker.internal:11434 beállításokat!

Part 1: Observer (A Szenzoros Hálózat)

Docker Socket Figyelő

Közvetlenül kérdezi le a Docker API-t:

  • Nem-nulla exit code detektálása
  • Restart loop észrevétele
  • Dead / OOMKilled állapot
  • Konténer újraindítás vezérlése

Valós Idejű Log Streamer

Követi a konténer kimenetét:

  • 500 soros szálbiztos körpuffer
  • Regex hibaminta illesztés (Traceback, CRITICAL, Error, Exception)
  • SSE eseménycsatorna a webes felületre

HTTP Szondák és Osztályozás

3 másodpercenként lekérdezi a végpontokat:

  • 2xx: Egészséges működés
  • 4xx: Soft szuggesztió (EMBERI feladat, nem javítja automatikusan)
  • 5xx / Timeout: Hard crash jelzés
Csúszóablakos Deduplikáció: SHA-256 lenyomatokat képez. Egyetlen rossz újraindulás pontosan 1 crash eseményt kelt léptetett számlálóval, kizárva a másodpercenkénti eseményáradatot.

Part 2: Analyst (Szemantikus Keresés és Diagnózis)

AST Logikai Daraboló (chunker.py)

  • A subject kifejezetten tiltja a fix méretű darabolást (pl. 500 karakter).
  • Python ast modullal logikai függvény- és osztályhatárok mentén szeletel.
  • Minden chunkhoz SHA-256 lenyomatot rendel.
  • A ChromaDB PersistentClient a .chroma mappában újraindításkor átugorja a változatlan kódkockákat.

Traceback Által Vezérelt RAG

  • Kivonja a hibalognak a pontos fájlneveit, sorait, függvényeit és kivételtípusát.
  • Koszinusz-hasonlósági keresést futtat a helyi all-MiniLM-L6-v2 modellel.
  • A releváns kódszeleteket átadja a helyi Ollama promptnak.

Strukturált JSON Diagnózis és Anti-Hallucináció

Szigorú JSON kimenetet kényszerít ki: {"summary": "...", "files": ["eleresi/ut"]}. A gyanúsított fájlokat összeveti a valós indexelt fájlokkal — az ágens nem találgat és nem nyúl képzeletbeli elérési utakhoz.

Part 3: Wisdom Loop (Cselekvés és Rollback)

Diff-mentes JSON Patcher

A diffeket a subject szigorúan tiltja. A patch a teljes módosított fájltartalmat adja vissza: {summary, files: [{path, op, content}]}.

Sanity Bounds (Lemezre írás előtt)

  • Legfeljebb 3 fájlt módosíthat
  • Max. 60%-os méretcsökkenés
  • Üres vagy placeholder fájlok tiltása
  • RAG markerek szűrése
  • Python szintaxis-ellenőrzés

GitManager és Ágkezelés

Pre-loop snapshot sha mentése. Atomi írás os.replace-szel. Automatikus commit a dedikált iow/auto-heal ágra.

A 3-Kísérletes Garancia: Ha 3 javítási kísérlet után sem áll talpra a célalkalmazás, a GitManager azonnal kiad egy git reset --hard <pre_loop_hash> parancsot, újraindítja a konténert, és tisztán hagyja a repót.

Dinamikus Biztonsági Korlátok (iow.config.yml)

Hard-code-olt időzítések tiltottak. Minden beállítás közvetlenül lemezről frissül:

Az 5 Megkerülhetetlen Szabály

  • Single-Flight: Egyszerre pontosan 1 javítási ciklus futhat. Kizárja a versenyhelyzeteket.
  • Cooldown: 300 mp türelmi idő ugyanarra a hiba-szignatúrára.
  • Rate Limit: Legfeljebb 5 javítás egy csúszó órán belül.
  • Hard Cap: Legfeljebb 20 javítás a folyamat élettartama alatt.
  • Kill-Switch: A kill_switch: true azonnal tilt minden új kísérletet.

Dinamikus mtime Újratöltő

A SafetyManager figyeli a fájl módosítási idejét (os.path.getmtime). A konfiguráció átírása azonnal érvényesül az ágens vagy a konténer újraindítása nélkül!

# demo_app/iow.config.yml
grace_period: 20
cooldown: 300
rate_limit_per_hour: 5
hard_cap: 20
kill_switch: false

Chapter VI: Bónusz Képességek (bonus/)

Tiny Symptom Classifier

Gyorsítótárazza az ellenőrzött javításokat. Ismert hiba esetén átugorja az LLM-et (Fast Path), 20 másodpercről 0.01 másodpercre csökkentve a javítás idejét.

Second Opinion Konszenzus

Két független elemzési stratégiát futtat (Konzervatív vs Rendszerszintű). Csak akkor indul el a kódjavítás, ha mindkét vélemény megegyezik a hibás fájlban.

Human-in-the-Loop PR-ek

Automatikus commit helyett izolált iow/review/* ágat, vizuális Unified Diff-et és dashboard jóváhagyási gombot nyújt az emberi operátornak.

Minden bónusz modul a bonus/ könyvtárban található, így a kötelező rész kódja teljesen tiszta marad.
