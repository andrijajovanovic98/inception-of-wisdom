Part 1: Observer - A Szenzoros Idegrendszer

Az Observer feladata a célkonténer életciklusának folyamatos monitorozása, a stdout/stderr logok valós idejű követése, HTTP szondák futtatása, a hibajelzések osztályozása és a hibaesemények deduplikációja.

Subject Előírás: "Observe: figyeli a Docker eseményeket, szinte valós időben streameli a logokat, HTTP végpontokat tesztel, és az eseményeket egyetlen incidenssé vonja össze."

Docker Socket Vizsgálat (docker_monitor.py)

Socket Kommunikáció

A /var/run/docker.sock csatolásával az ágens közvetlenül a host Docker démonját kérdezi le a Python docker SDK-val.

  • Nem-nulla exit code: status == "exited" and exit_code != 0
  • Crash loop észrevétele: status == "restarting" számlálóval
  • Halott konténer: c_state.get("Dead") or c_state.get("OOMKilled")

Konténer Újraindítás

A DockerMonitor ellenálló újraindító primitívet nyújt:

def restart_container(self, timeout=10):
    container = client.containers.get(self.container_name)
    container.restart(timeout=timeout)
    return True
Értékelői Kérdés: "Mi történik, ha a Docker démon újraindul?"
Válasz: A DockerMonitor elkapja az API hibákat, és automatikusan újracsatlakozik anélkül, hogy az ágens összeomlana.

Valós Idejű Log Streamer (log_streamer.py)

Stream Ciklus és Körpuffer

  • Követi a container.logs(stream=True, follow=True) folyamot egy háttérszálban.
  • 500 soros szálbiztos körpuffert kezel (collections.deque(maxlen=500)).
  • Server-Sent Events (SSE) csatornán keresztül azonnal elküldi a sorokat a dashboardnak.

Regex Hibaminta Illesztés

Minden sort összevet a kompilált mintákkal:

DEFAULT_ERROR_PATTERNS = [
    r"Traceback \(most recent call last\):",
    r"CRITICAL:",
    r"Error:",
    r"Exception:"
]

Találat esetén azonnal jelzést küld a központi EventManager-nek.

HTTP Szondák és Jelzésosztályozás (http_probe.py)

Hard Crash vs Soft Szuggesztió

A subject szigorúan megköveteli a hibák és szuggesztiók szétválasztását:

  • Hard Signal (Crash):
    • HTTP 5xx Server Error
    • Connection refused / megszakadt kapcsolat
    • Timeout (nem válaszoló célalkalmazás)
    • 👉 Automatikusan elindítja a Wisdom Loop öngyógyítást!
  • Soft Signal (Szuggesztió):
    • HTTP 4xx (pl. 404 Not Found, hiányzó route)
    • 👉 Csak megjelenik a dashboardon az ember számára. SOHA nem javítja automatikusan!

Folyamatos Poller

Időzítése az iow.config.yml fájlból olvasandó:

# demo_app/iow.config.yml
target:
  service_url: "http://demo_app:5000"
  probe_interval_seconds: 3
  probe_urls: ["/", "/healthz"]

Késleltetést mér milliszekundumban a felület számára.

Esemény Deduplikáció (event_manager.py)

Az Eseményáradat Problémája

Ha a konténer beragad egy újraindulási hurokba, percenként több tucat hiba keletkezik. Deduplikáció nélkül az LLM túlterhelődne az azonos hibaüzenetekkel.

Csúszóablakos Megoldás

  • SHA-256 ujjlenyomat: SHA256(forras + tipus + kulcs).
  • Csúszóablakos időbélyeg cache:
    • Crash ablak: 10 másodperc
    • Szuggesztió ablak: 60 másodperc
  • Az ablakon belül érkező duplikátumok egy számlálót léptetnek (x3) új esemény dobása helyett.
Eredmény: 1 valós hibaforrás = 1 tiszta ObserverEvent.

Observer REST API és SSE Csatorna (observer_api.py)

FastAPI Végpontok

  • GET /api/observer/status: Konténer állapot, Docker státusz, HTTP késleltetés.
  • GET /api/observer/logs: A körpuffer legutóbbi sorainak pillanatképe.
  • GET /api/observer/events: A deduplikált incidensek listája.
  • GET /api/observer/stream: Server-Sent Events (SSE) folyamatos adatfolyam a webes terminálhoz.
Defense Tipp: Mutasd meg a vizsgáztatóknak, hogyan gördülnek valós időben a logok a fekete terminálablakban az SSE-n keresztül!

Part 1 Védési Kérdések és Válaszok

Gyakori Értékelői Kérdések:

  • K: Honnan tudja az Observer, hogy a konténer összeomlott?
    V: Kétirányú detektálás: a Docker socket állapota (exited, restarting, dead) ÉS a HTTP szondák (5xx, connection refused).
  • K: Miért nem javítja automatikusan a 4xx hibákat?
    V: Subject előírás: a 4xx funkcionális hiányosságot vagy klienshibát jelent, nem pedig rendszerszintű összeomlást. Csak a hard hibák aktiválják az öngyógyítást.
  • K: Hogyan akadályozod meg az eseményáradatot?
    V: Az event_manager.py csúszóablakos deduplikációja SHA-256 ujjlenyomat alapján 10 másodpercig egyetlen incidenssé vonja össze az ismétlődő hibákat.
